Abstract

This memo documents the work of Sri Pranav Tene, a software engineer based in Hyderabad and the founder of Lupyd. It covers a privacy-first social platform, end-to-end encrypted messaging, peer-to-peer transport, and a handful of smaller tools, and describes how to start a collaboration with the author.

1. Introduction

The author works in the layer where hard technical ideas become dependable products: the part after the whiteboard and before the user notices anything at all.

the middle two are the fun part

Most of that work happens at Lupyd [LUPYD], a privacy-focused social and collaboration platform built from the ground up: Rust on the server, React and Tauri on the clients, and MLS, WebSockets, WebTransport and WebRTC in between. Outside it, the author writes Rust, C++, TypeScript, Flutter and Go, and has shipped audio processing, GPU compute, mobile apps, smart contracts and a programming language.

Section 3 lists the work. A longer account of the author is filed separately as RFC 1.

2. Conventions Used in This Document

The key words "MUST", "MUST NOT", "SHOULD", "SHOULD NOT", and "MAY" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

The author's own work is held to the following:

  • User data MUST NOT be collected merely because it can be.
  • Encryption SHOULD be end-to-end. The server is not a trusted party.
  • A round trip that can be removed SHOULD be removed.
  • A dependency MAY be added when it pays rent.
  • Code MUST remain understandable by whoever maintains it next, including the author in a year.
read these as promises, not slogans
